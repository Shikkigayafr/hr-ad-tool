## 2026-11-10 — исправления безопасности аутентификации
- Получен origin/main, исходный код соответствует 06c3cb2; локальные секреты и БД не изменяются.
- Сессии привязаны через HMAC к текущему паролю: старые cookie отзываются при смене/сбросе пароля без миграции БД.
- Socket.IO проверяет ограничения временного пароля; соединения отзываются при выходе, удалении и смене пароля, права повторно проверяются перед рассылкой.
- LDAPS всегда проверяет сертификат и имя DC; удалён запасной пароль сервисной учётки.
- Исправлено доверие к X-Forwarded-For за одним proxy; учтён HTTPS через доверенный X-Forwarded-Proto.
- Защита Origin, проверка типа JSON, no-store для API/HTML, CSRF только своему origin, nosniff и запрет frame.
- Явный файл секрета читается с отказом при ошибке; production требует SECRET_KEY, шаблонный ключ отклоняется.
- В Set-Telegram-Proxy.ps1 добавлен обязательный UTF-8 BOM. Добавлены регрессионные тесты, тестовое окружение явно выключает Яндекс 360.

## 🖥️ Инфраструктура и окружение
- **Где разрабатывается:** Основной ПК (Windows, Git Bash, VS Code). ПК **не введен в домен**.
- **Целевая среда (боевая):** Виртуальная машина (ВМ) развернута на гипервизоре **Proxmox**.
- **Домен (AD):** В компании (Эвостор) развернут Active Directory (контроллер домена). ВМ будет иметь сетевой доступ к контроллеру для работы LDAP.
- **СБИС (Saby):** В компании используется СБИС. В нем настроены отделы (Отдел исходящих звонков, Офис, Колл Центр и т.д.). Настроена интеграция LDAP.
- **Сеть:** В локальной сети есть контроллер домена, к которому мы будем подключаться по IP (например, `ldap://192.168.88.10`).

## 🟢 Что уже готово (Сделано)
1. **Архитектура**: Приложение на Flask (Python). База данных SQLite (через SQLAlchemy).
2. **Авторизация**: 
   - Сессии, защита страниц (без входа не попасть на `/create` и `/employees`).
   - Выход из системы (`/api/logout`).
3. **Роли и права**:
   - **admin**: может всё. Создавать в любой отдел, выдавать роль "Старший", повышать и удалять.
   - **hr**: может создавать только в свой отдел и только "Стажер" или "Основной". Не может повышать.
4. **Интерфейс (Frontend)**:
   - Адаптивный дизайн в стиле компании (темная шапка, синие кнопки, карточки).
   - Модальное окно входа (появляется автоматически, если не авторизован).
   - Выпадающие списки отделов (согласно структуре СБИС) и квалификаций.
   - Таблица сотрудников с кнопками "Повысить" и "Удалить" (с подтверждением).
5. **Имитация AD (Режим DRY_RUN)**:
   - Написан `ad_utils.py` для работы с LDAP (ldap3).
   - Включен режим `DRY_RUN=true`, который имитирует создание в AD без реального подключения к контроллеру домена.
6. **GitHub**: Проект выгружен на GitHub. Настроен `.gitignore` (защита паролей).
