# Отладочные скрипты Saby

Разовые скрипты, с помощью которых изучалось API Saby (СБИС). **Они обращаются к боевому Saby** с логином и паролем из `.env` (`SABY_LOGIN`, `SABY_PASSWORD`, `SABY_ORG_INN`), а часть из них **создаёт записи** (сотрудников, подразделения). Запускайте только осознанно и вручную, из корня проекта.

| Скрипт | Что делает | Меняет данные? |
|---|---|---|
| `get_ids.py` | список организаций и подразделений (ID для `.env`) | нет |
| `get_positions.py` | список должностей (`sabyPosition.List`) | нет |
| `get_department_info.py` | тип структуры подразделения (`sabyDepartment.Read`) | нет |
| `probe_department_methods.py` | пробует разные методы `sabyDepartment.*` | нет |
| `probe_position_payload.py` | печатает эталонный запрос `UpdatePosition` | нет |
| `probe_create_user.py` | создаёт тестового сотрудника через `saby_utils` | **да** |
| `probe_cadre_structure.py` | создаёт тестовое подразделение и сотрудника | **да** |

Названия `probe_*` выбраны намеренно: `pytest` не должен принимать эти скрипты за тесты (тесты проекта лежат только в `tests/`).

Контекст и гипотезы по управленческой структуре — в `CLAUDE.md` (раздел «Известные ограничения Saby»).
